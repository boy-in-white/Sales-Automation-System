# ТТН і передача в Ledgerly

## Як це працює

1. Клієнт вибирає післяплату з передоплатою 100 грн або повну оплату товару.
2. Repliq збирає ПІБ, телефон, населений пункт з областю й відділення/поштомат.
   Адреса звіряється з довідником НП; клієнт бачить її повністю.
   Після підтвердження зведення товарів та адреси створюється одна
   ТТН на посилку. Чекати перевірки банку не потрібно.
3. Сам Ledgerly публікує картку в своїй темі відправлення: товари, адреса,
   суми, ТТН, акаунт відправника та кнопка **✅ Оплату перевірено**.
4. Перевір надходження в банку й натисни кнопку в Ledgerly або Repliq.
   Позначка синхронізується між програмами й може бути скасована.
5. Після фактичної передачі посилки натисни звичайну кнопку відправлення
   Ledgerly. Далі працюють його облік, відстеження та групи.

Квитанція не доводить надходження коштів. Створена ТТН також не означає оплату
чи відправлення. Без твоєї позначки оплати кнопка відправлення цього
імпортованого замовлення не спрацює.

При післяплаті у ТТН записується **повна вартість товарів мінус 100 грн**.
При повній оплаті повторного стягнення за товар немає: одержувач оплачує
лише доставку. Ledgerly обліковує повну вартість товарів один раз.
Кілька різних речей мають одну ТТН і окремий складський облік кожної позиції.

## Два акаунти Нової пошти

Файл: `private/shipping-settings.json` у папці Repliq. Там секретні ключі:
редагуй локально, не надсилай файл у чат і не публікуй його.

- `profiles.first.nova_api_key` — перший акаунт, **1–15 числа включно**.
- `profiles.second.nova_api_key` — другий акаунт, **16–останнє число місяця**.

Календар працює за часом Києва та повторюється щомісяця. Перемикається
тільки створення нових ТТН. OLX, Telegram, SQL та вже створені накладні
не перемикаються. Раніше створена ТТН залишається прив'язаною до свого акаунта.

Перший профіль налаштований із наявного ключа Ledgerly. У другому залишене
порожнє поле `nova_api_key`: встав ключ API другого кабінету Нової пошти.
Ключ береться в кабінеті відповідного акаунта у розділі API.
Відправлення налаштоване зі **Львова, поштомат №65774** для обох профілів.
Після додавання другого ключа його відправник і контакт визначаються
автоматично, якщо вони однозначні. За кількох контактів потрібен явний вибір.
Відсутній другий ключ зупиняє створення ТТН у другій половині місяця;
підміни першим акаунтом немає. Безпечна помилка відсутнього ключа автоматично
перевіряється знову після його заповнення, поки замовленню менше доби.

## Розміри посилки й налаштування

У кожного профілю є `parcel`: початкова оцінка малої посилки —
**1 кг, 30×20×8 см** на одну річ. Для кількох речей вага й висота
збільшуються. Це технічні припущення: заміни фактичними замірами запакованої
посилки. Автоматично обробляються до трьох речей в одній посилці;
більше або нестандартні габарити потребують перевірки. Тип вантажу — посилка,
не документи. Фактична доставка оплачується за тарифами перевізника.

За вибором власника в обох профілях явно встановлено
`cod_mode: money_transfer`: зворотна доставка коштів (грошовий переказ).
Поточний бажаний спосіб отримання — готівкою у відділенні; картку для виплати
Repliq у запит не додає. Картка передоплати з payments.json не є карткою
отримання післяплати й у запит створення ТТН не копіюється.

Режим `money_transfer` задає послугу переказу, а не гарантує спосіб її виплати.
Сам по собі він не вимикає автозарахування у кабінеті НП/NovaPay. Якщо воно
підключене, спосіб отримання потрібно звірити там. Непідтверджені параметри
API для примусової видачі готівки програма не додає. За інформацією NovaPay,
приватний клієнт може отримати переказ у відділенні наступного дня після
оплати посилки одержувачем; потрібен документ, що посвідчує особу.

Для бізнес-відправлень ФОП/юросіб NovaPay вимагає спершу зарахування на
рахунок, тому готівковий режим не слід вважати способом бізнес-виплати.
Договірний `afterpayment` залишається окремою можливістю коду; автоматичного
перемикання на нього в явно налаштованих профілях немає.
[Післяплата для приватних клієнтів](https://novapay.ua/pisljaplata/),
[правила для підприємців](https://novapay.ua/novapay-zmini-u-vidachi-gotivki-pidpriiemtsyam-u/).

У Ledgerly в `.env` додані лише два шляхи: `REPLIQ_BRIDGE_DB` та
`REPLIQ_SHIPPING_SETTINGS`. Обидві програми працюють на одній машині й бачать
спільну папку `repliq-ledgerly`. При перенесенні зміни абсолютні шляхи.
Repliq залишається читачем складської SQL; бізнес-записи робить Ledgerly.

## Відновлення та завершення

- Старі замовлення автоматично не перетворюються на ТТН. Сценарій діє
  для нових рахунків, створених після встановлення цієї версії.
- OLX Доставка оформлюється в OLX. Цей механізм не створює для неї незалежну
  накладну: [пояснення](OLX_DELIVERY.md).
- Зміна товарів або адреси після створення ТТН потребує перевірки
  наявної накладної; друга автоматично не створюється.
- Якщо результат створення загубився через обрив зв'язку, автоповтору немає.
  Перевір кабінет НП, щоб уникнути двох накладних на одну угоду.
- «Завершити угоду» у Repliq очищає розмову, зберігаючи вже створену ТТН
  та її передачу в Ledgerly. Ще не почате створення зупиняється. Скасування
  замовлення — окрема дія; створену накладну в НП потрібно скасувати окремо.

Тести використовують підставні ТТН. Створення реальної накладної через API
потрібно перевірити на першому замовленні, зокрема режим післяплати за договором.
Поточні боти потрібно перезапустити для завантаження нового коду.

Джерела: [API Нової пошти](https://novaposhta.ua/for-business/cooperation/integration/),
[відправка з поштомата](https://novaposhta.ua/send/from-parcel-locker/).
# Скасування в Ledgerly · 2026.11.08.8

Явне **Скасувати** на картці створеного Repliq замовлення скасовує обробку й ставить
видалення накладної в чергу. Дія доступна власнику на поточній картці до позначки
фактичної відправки. Саме очікування оплати не є командою видалення.

Repliq читає стан конкретної ТТН з початкового акаунта НП. Для ще не переданої
накладної надсилається `InternetDocument.delete` з одним `DocumentRefs` — збереженим
Ref саме цього документа. Формат звірено з [відкритим кодом клієнта API](https://github.com/sirkostya009/go-novapost/blob/master/internet_document.go).
Зміна половини місяця не переключає акаунт видалення. Ключ з іншим відбитком,
відсутній Ref або фактичний рух посилки блокують автоматичне видалення.

Картка відображає чергу, підтверджене видалення, відмову або невідомий результат.
Після втрати відповіді на запис повторного видалення немає. Старі скасування,
зроблені до цієї версії, не запускають масове видалення заднім числом.
Перевірено з підставним API; реальні накладні під час розробки не видалялися.
