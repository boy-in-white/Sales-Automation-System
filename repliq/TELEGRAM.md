# Telegram · особисте завершення угод

Одна приватна група з темами. **Одна тема = один OLX-діалог.**
Керування каталогом і оголошеннями виконується **особисто цьому боту**, лише
з твого акаунта: кнопки «Товари», «Оголошення», «Додати», «Змінити», «Вимкнути»
та «Оновити каталог». Старі текстові команди також підтримуються. Докладно: [CATALOG.md](CATALOG.md). У групі ці команди не працюють.
Repliq використовує окремого Telegram-бота; токен Ledgerly сюди не копіюй.
Додаткові бібліотеки, платні API, публічний сервер чи webhook не потрібні.

## Як працює діалог

Тема створюється після першого нового звернення клієнта. Усередині — цитати
«Клієнт», «Бот», «Ти» та постійна панель «Бот / Вручну». Якщо дозволяють права
адміністратора, панель закріплюється. Нові стани оновлюють її без потоку однакових повідомлень.

Бот сам уточнює товар, розмір, колір, кількість і перевіряє SQL. Підтримується
кілька позицій. Потім пропонує три способи оформлення й аналізує вибір:

- OLX Доставка — очікує оформлення в самому OLX, далі підключає власника.
- Післяплата — реквізити, 100 грн, запит даних відправки та квитанції.
- Повна оплата — точна сума товарів, реквізити, дані відправки й квитанція.

Для оплати за реквізитами діалог переходить у ручний режим, коли дані
підтверджені покупцем і квитанція отримана або виникло питання, яке потребує власника. Надходження коштів бот не
підтверджує. Для кількох речей через OLX власник узгоджує правильне оформлення.
Реквізити зберігаються в private/payments.json; пояснення: [SHOP.md](SHOP.md).

Історія надходить повідомленнями з цитатами, без TXT. Довгі повідомлення діляться,
короткі репліки історії об'єднуються. Уже показані повідомлення не дублюються
при передачі власнику. Посилання на вкладення додаються, якщо їх надає OLX;
фото/відео не завантажуються на VM. Межа історії — 5000 повідомлень і 2 МіБ.

## Одноразове налаштування

1. Створи **окремого** бота через офіційного `@BotFather`, командою `/newbot`.
2. Створи приватну групу для себе й Repliq, увімкни в налаштуваннях **Теми**.
3. Додай нового бота як адміністратора з правом керувати темами й надсилати
   повідомлення. Особисті повідомлення — для налаштувань; відповіді
   покупцям надсилаються з відповідних тем групи.
4. Скопіюй `config/telegram.example.json` у `private/telegram.json`.
5. Встав токен у `bot_token`. Поки залиш `enabled: false`.
6. Напиши `/start` боту особисто, а в створеній групі — `/id`.
7. У папці Repliq, коли основний бот зупинений, виконай:

   ```sh
   .venv/bin/python -B telegram_info.py
   ```

   Команда показує тільки ID. Для групи потрібний від'ємний `chat_id`, для
   `owner_ids` — твій додатний `owner_id`. Рядок із типом `private` означає
   особистий чат; його ID не став замість ID групи.
8. Заповни решту файла й увімкни `enabled: true`:

   ```json
   {
     "enabled": true,
     "bot_token": "TOKEN_FROM_BOTFATHER",
     "group_id": -1001234567890,
     "owner_ids": [123456789]
   }
   ```

   Це приклади ID, заміни їх своїми. Токен у чат надсилати не потрібно.
   Файл міститься в `private/`, поза Git. За потреби встанови права `600`.

Запускай звичайний `responder.py` або `--worker`. Telegram-міст починає
працювати в тому самому процесі. Перевіряються приватність групи, теми й
права бота. Якщо налаштування відсутні, звернення зберігаються локально,
а діалоги оформлення залишаються без автоматичних відповідей до налаштування.

## Як відповідати

**Просто напиши в темі клієнта.** Текст одразу піде саме цьому покупцю в OLX.
Відповідати через Reply також можна; `/say` більше не потрібний.
У загальній темі, особистому чаті бота та чужих темах текст клієнтам не надсилається.
Якщо потрібна внутрішня нотатка, почни її з `/note` — вона залишиться в Telegram.

Під повідомленнями — тільки дві кнопки: **auto** та **я**. Галочка показує
активний режим. Один натиск зберігає режим саме цього клієнта. Після 40 хвилин
без твоєї відповіді чи дії ручний режим автоматично повертається в auto;
нові повідомлення покупця цей час не подовжують.

Назва теми й заголовок картки: **ім’я профілю OLX · ID · товар**. ПІБ для
доставки не підміняє ім’я профілю. Якщо OLX не повертає ім’я, тимчасово
показується «Клієнт · ID …»; імена кешуються й оновлюються у фоні. Наявні
теми перейменовуються зі збереженням їхніх ID, історії та прив’язки клієнта.

Оплата й відправлення ведуться у Ledgerly. Приватне сповіщення про OLX
Доставку не перемикає діалог з auto на ручне керування.

Старі /done, /pause, /resume, /history, /say збережені для сумісності.
/done працює як завершення угоди, /cancel закриває діалог до явного ввімкнення.
Завершення не списує товар у Ledgerly. Оплату й відправку перевіряє власник.
Фото/документи з Telegram у OLX ця версія не надсилає — підтримується текст.

### Команда /clear

Власник може написати **`/clear`** в особистому чаті з ботом або в потрібній
темі групи. Це лише текстова команда, без кнопки. Вона прибирає доступні
повідомлення саме тут; інші теми, історію OLX, пам’ять консультації, замовлення,
оплати й ТТН не змінює. Картки з робочими inline-кнопками залишаються.
У групі боту потрібне право адміністратора «Видалення повідомлень».

Telegram дозволяє видалення переважно протягом 48 годин. Бот запам’ятовує
лише номери повідомлень, які отримав або надіслав після цього оновлення;
старі невідомі повідомлення командою прибрати не вийде. Журнал зберігається
локально у `telegram-messages.sqlite3` поруч із базою Repliq, без текстів
листування, і автоматично очищається. `/clear@Ім’яБота` також підтримується;
команди для іншого бота і від інших користувачів ігноруються.

## Межі доступу й відновлення

- Обробляються лише явно дозволені оголошення: додані особистою командою
  або через `advert_ids` у `shop.json`. Налаштування Telegram мають пріоритет.
  Без дозволених прив'язок інші чати бот не читає.
- Відповіді приймаються тільки від `owner_ids`, тільки з указаної групи та
  прив'язаної теми. General, чужі теми, інші боти, анонімні й переслані повідомлення ігноруються.
- Маршрут зберігається за account + OLX UUID + buyer ID + advert ID + Telegram topic ID.
  Перед відправленням звіряються обліковий запис і співрозмовник OLX.
- Повторний Telegram update не створює другу відповідь. Редагування старого
  Telegram-повідомлення нічого повторно не надсилає. Текст старший за 15 хвилин пропускається.
- Звичайні старі OLX-чати не опрацьовуються. Уже передані власнику чати
  після перезапуску продовжуються з останнього збереженого лічильника,
  включно з повідомленнями, які прийшли під час зупинки.
- Повернення боту скидає контекст тільки цього клієнта; інші діалоги продовжуються незалежно.
- Telegram працює окремим потоком і не блокує перевірку OLX. Повідомлення
  групі надсилаються з паузою щонайменше 3,2 с; діє черга й обробка HTTP 429.
- Після неоднозначної помилки надсилання автоматичного повтору немає.
  Перевір OLX або Telegram вручну. `responder.py --status` показує нез'ясовані випадки.
- Якщо результат створення теми невідомий, Repliq не створює дубль.
  Перевір групу, обери правильну тему або створи її вручну, а потім введи
  `/bind OLX_UUID` у ній. OLX UUID буде в консолі та `--status`.
- Зміни токена, групи, власників і ручного `shop.json` застосовуються після перезапуску.
  Прив'язки оголошень із приватного чату застосовуються відразу.
  Уже розпочате мережеве надсилання може завершитися після команди паузи.
