# OLX Доставка для ФОП і передача в Ledgerly

Перевірено 7 листопада 2026 року. Це результат дослідження й схема інтеграції;
автоматичне підтвердження OLX Доставки в програмі не реалізоване.

Актуальна реалізація сповіщень, Укрпошти й результати перевірки від
9 листопада — у [DELIVERY_MONITOR.md](DELIVERY_MONITOR.md).

## Що підтверджено

Для бізнес-профілю OLX можна налаштувати отримання виплат на IBAN ФОП.
Потрібні перевірені бізнес-дані й платіжні реквізити в самому OLX. Це окремо
від реквізитів, які Repliq надсилає покупцям для звичайної передоплати.
[Інструкція OLX для бізнес-продавця](https://business.olx.ua/stan-avtoryzovanim-biznes-prodavtsem-na-olx/).

Продавець підтверджує справжнє замовлення в «OLX Доставка → Мої продажі».
Після підтвердження OLX надає накладну. Відправляти потрібно за цією накладною:
самостійно створена ТТН не є заміною накладної відповідної угоди OLX.
[Офіційна інструкція про нове замовлення](https://help.olx.ua/olxuahelp/s/article/%D0%BD%D0%BE%D0%B2%D0%B5-%D0%B7%D0%B0%D0%BC%D0%BE%D0%B2%D0%BB%D0%B5%D0%BD%D0%BD%D1%8F-V33).

У відкритій українській документації Partner API знайдені оголошення,
повідомлення та службові дані, але не знайдені методи списку угод OLX Доставки,
їх підтвердження та отримання накладних. Тому висновок за доступними даними:
повний сценарій «покупка → автоматичне підтвердження → ТТН» через поточний
публічний український API підтвердити неможливо.
[Документація OLX Україна](https://developer.olx.ua/api/doc).

Польський портал описує окремі можливості Delivery як доступні для Польщі.
Це не підтверджує наявність цих методів в Україні й не дозволяє підставити
польські адреси API у Repliq.
[Офіційна документація OLX Польща](https://developer.olx.pl/api/doc?_locale=en).

Окремий партнерський доступ, якщо OLX його надає для України, потрібно
підтвердити в OLX і отримати його офіційну схему. Наявні `read/write/v2`
самі по собі не є доказом такого доступу. Назви недокументованих методів
і поля відповідей не вигадуються.

## Що вже є в Ledgerly

Перевірено код `handlers.py`, `callbacks.py`, `incoming_group_listener.py`,
`business_db.py`, `parser.py`, `validator.py` та `ui.py` у проєкті Ledgerly.

- Дані товару, ціна й одна ТТН проходять перевірку та створюють заявку.
- Ledgerly сам надсилає картку в тему відправлення з кнопкою «Відправлено ✓».
- Подальші стани й облік веде Ledgerly; саме створення картки не означає
  успішний продаж або банківську виплату.
- Поточна модель замовлення прив'язана до одного товарного варіанта.
  Кілька різних речей в одній посилці потребують окремої підтримки позицій:
  не можна кілька разів записати ту саму ТТН як незалежні продажі.

Просто надіслати повідомлення від Repliq у групу недостатньо. Telegram не
передає ботам повідомлення інших ботів, а груповий обробник Ledgerly також
відхиляє `is_bot`. Роль `repliq_reader` залишається лише для читання складу.
[Пояснення Telegram](https://core.telegram.org/bots/faq#why-doesn-39t-my-bot-see-messages-from-other-bots).

## Надійний зв'язок між двома програмами

Для звичайних посилок Нової пошти вже є окрема локальна SQLite-черга
та приймач Ledgerly: [SHIPPING.md](SHIPPING.md). Repliq записує власні події;
Ledgerly читає їх і через свої наявні функції створює заявки та Telegram-картки.
Repliq не отримує права напряму змінювати склад, продажі або фінанси Ledgerly.

У події мають бути:

- стабільний унікальний ключ події й ідентифікатор акаунта OLX;
- справжній ID угоди OLX, ID оголошення, окремо ID чату;
- ID товарів/варіантів Ledgerly, розміри, кольори, кількість і погоджені ціни;
- перевізник і ТТН саме з угоди OLX;
- загальна вартість товарів, відома комісія окремо; невідома комісія — `null`;
- джерело підтвердження: офіційна відповідь OLX або перевірка власником.

Повторна доставка однієї події не створює другу заявку. Потрібні унікальність
за угодою, збережений результат обробки, відновлення після перезапуску й
перевірка прив'язки акаунт → угода → оголошення → товар. Самого імені покупця,
тексту «я оформив», вкладення або номера чату для цієї прив'язки недостатньо.

Лише Ledgerly публікує картку у своїй групі зі своїми кнопками. Для користувача
це одна картка в черзі відправлення, без обміну повідомленнями між ботами.
Приймач Ledgerly реалізований для звичайних ТТН НП. OLX Доставка до нього
автоматично не надходить: підтвердженого джерела її угод/ТТН з API OLX немає.

## Доступний процес зараз

1. Repliq погоджує товар, розмір і колір та очікує оформлення через OLX.
2. Власник підтверджує справжню угоду в профілі OLX й отримує її ТТН.
3. Товар, кількість, ціну та цю ТТН можна надіслати Ledgerly звичайним
   повідомленням від дозволеного користувача. Ledgerly створить картку у темі
   відправлення своїм наявним процесом.
4. Після фактичної відправки власник натискає «Відправлено ✓» у Ledgerly.

Сторонні посилання від покупця не відкриваються автоматично. Для повної
автоматизації перших двох кроків бракує документованого доступу OLX Україна
до угод доставки, підтвердження та накладних.
