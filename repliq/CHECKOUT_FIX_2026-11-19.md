# Reliq · контекст оформлення · 19.11.2026

Версія: **2026.11.19.2**.

## Причини збоїв

Перевірено збережені переходи проблемного живого діалогу. «Добре зараз все зроблю» стало ПІБ, а «добре зараз» — містом. Запис «Нова пошта номер 1» залишився всередині міста. Відділення з позначкою N*1 не розпізнавалося, після чого лічильник невдалих відповідей припиняв оформлення. В іншому діалозі слова «номер замовлення» помилково означали скаргу, а окремий «?» запускав пошук невідомої характеристики товару.

## Виправлена поведінка

| Репліка / ситуація | Дія |
| --- | --- |
| «Добре, зараз усе зроблю» | Коротке «Добре, я на зв’язку». Дані отримувача не змінюються; анкета не повторюється. |
| «Добре давайте передоплатою» після пропозиції післяплати | Прийняття саме погодженого способу; без нового переліку всіх варіантів. Без попередньої пропозиції сума уточнюється. |
| «Нова пошта номер 1», «НП №1», «Нова пошта N*1» | Розпізнається відділення №1; адреса перевіряється в довіднику перед підтвердженням. |
| ПІБ, телефон, населений пункт і відділення одним рядком або кількома повідомленнями | Поля збираються разом; помилка в телефоні не стирає ПІБ чи відділення. |
| Адреса й питання про тканину в одному пакеті | Дані зберігаються, питання отримує відповідь, адреса показується для перевірки. |
| «ТТН — це номер замовлення?» | Пояснення різниці між накладною перевізника та номером покупки, без відповіді про скаргу. |
| «?» після пояснення | Уточнення попередньої теми. Покупка, переказ або підтвердження адреси не виконуються повторно. |
| Прохання повідомити про прибуття | Пояснення відстеження поточної посилки, без підміни прибуття обіцянкою відправки сьогодні й без обіцянки непідключеного сповіщення. |

Відомі помилково збережені розмовні фрази очищаються при подальшому зборі адреси. Вкладені в старе поле міста дані відділення відновлюються. Готові накладні автоматично не переписуються; нова адреса вимагає нового підтвердження. Повторні неповні відповіді більше не переводять оформлення в режим «поверніться пізніше».
