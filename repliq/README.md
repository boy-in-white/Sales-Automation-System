## Що заповнити

Відкрий `shop.json`. Файл не містить секретів. Після змін перезапусти Repliq.

Для необов'язкового профілю товару (звичайне додавання тепер через Telegram):

| Поле | Що поставити |
|---|---|
| `advert_ids` | Номер оголошення OLX, наприклад `[123456789]`; це приклад |
| `ledgerly_product_id` | Справжній `product_id` з Ledgerly, не назва товару |
| `price_uah` | Ціна продажу у гривнях, наприклад `800`; зараз `null` |
| `description` | Тканина, склад і особливості товару |
| `measurements` | Справжні заміри виробу |
| `authenticity` | Правдива інформація про походження/оригінальність |
| `sizes` | Виправити тестові діапазони зросту й ваги |
| `size_chart_verified` | Поставити `true` після перевірки розмірної сітки |

**Справжні заміри виробів внесено в `garment_measurements`.** Для Suvene є
S/M/L/XL, для Gallery Dept — S/M/L. Пояс підписано нейтрально, без перерахунку
на обхват чи ширину. Орієнтири зросту M/L/XL приблизні; таблиця зросту та ваги
не вигадується. Докладно про дані й обмеження: [SHOP.md](SHOP.md).

У блоці `shop` заповни `delivery`, `payment`, `returns`, `discount` і
`order_instructions` звичайними українськими реченнями. Наприклад, в останньому
полі опиши ваш справжній спосіб оформлення. `null` означає «інформація невідома»,
а не відмову в доставці/обміні чи відсутність знижки. Невідомі умови бот уточнює.
Не записуй сюди паролі, закупівельні ціни чи дані інших покупців.

### Доступ до спільної бази

Скопіюй `config/responder-settings.example.json` у
`private/responder-settings.json` і заміни `database_url`:

```json
{
  "database_url": "postgresql://repliq_reader:YOUR_PASSWORD@127.0.0.1:5432/olx_business"
}
```

Альтернатива — змінна середовища `REPLIQ_DATABASE_URL` (має пріоритет).
Використовуй окремого користувача читання. Приклад надання прав власником бази:
`sql/repliq_reader.sql`. Пароль встановлюється окремо через `\password
repliq_reader` у psql; SQL-файл сам не задає пароль.

Номери товарів можна знайти таким запитом у своїй базі:

```sql
SELECT DISTINCT product_id, product_name
FROM analytics.v_inventory_stock
ORDER BY product_name;
```

SQL-модуль має одну повторно використовувану сесію, режим лише читання,
ліміт підключення 3 с, виконання запиту 2 с та паузу 30 с при проблемах бази.
Невідома/недоступна база ніколи не означає «товар є». Ціни продажу поки
налаштовуються у `shop.json`: собівартість партії з Ledgerly не є ціною продажу.

## Встановлення та запуск

У Terminal, у папці `Sales Automation System/repliq`:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Підтримується Python 3.9+, рекомендовано 3.11+. Залежність лише одна: psycopg
для PostgreSQL. Авторизація OLX, уже збережена в `private/`, використовується
автоматично. Інструкція з авторизації збережена в `OAUTH.md`; описи старого
фіксованого автовідповідача в тому файлі історичні, актуальний запуск — тут.

Після заповнення даних відкрий **«Запустити автовідповідач.command»**.
Або виконай:

```sh
.venv/bin/python -u -B responder.py
```

Спочатку з'явиться повідомлення «Чекаю нові повідомлення». Тільки після цього
надсилай тестове повідомлення з іншого акаунта.

Відповіді надсилаються автоматично. У консолі нічого підтверджувати не потрібно.
Залиш вікно Terminal відкритим; закриття вікна або Ctrl+C зупиняє програму.
Повідомлення, які вже були до запуску, не отримують автоматичної відповіді.

Після першого нового звернення у Telegram з'явиться окрема тема з цитатами.
Бот консультує, пропонує оформлення, надсилає реквізити та збирає дані й квитанцію. Просто пиши в темі:
повідомлення надходитимуть цьому клієнту. Кнопка **«✅ Завершити угоду»**
повертає чат боту й очищає старий вибір. Вже наявні повідомлення не запускають
нову консультацію — тільки наступне нове звернення.

Наявність, покупець і стан діалогу перевіряються повторно перед надсиланням.
При неоднозначному результаті мережевого надсилання повтору немає: перевір OLX.

### Необов'язковий ручний режим для тестів

Звичайний запуск працює автоматично. Для окремого тесту з підтвердженнями:

```sh
.venv/bin/python -u -B responder.py --manual
```

У цьому режимі `так` підтверджує показану відповідь, `ні` пропускає, `текст`
дозволяє її змінити. `--worker` запускає звичайну автоматичну обробку без запиту вводу.

## Тест без клієнтів

Відкрий **«Демо автовідповідача.command»**. Або:

```sh
.venv/bin/python -B responder.py --demo
```

Демо використовує тільки вигадані залишки: S/M/L по 2 шт. кожного кольору,
XL — 0. Можна по черзі вводити «штани Suvene», «який розмір», «175/68»,
«чорний», «хочу замовити». Виробничий процес не використовує ці залишки.

Офлайн-перевірки (для самостійного виконання):

```sh
.venv/bin/python -B -m unittest discover -s tests -v
```

Додані сценарії: ізоляція клієнтів, зміна товару, розмір між двома значеннями,
SQL=0, недоступна SQL, зміна залишку перед надсиланням, нове повідомлення під
час підтвердження, подвійне підтвердження та невідомий результат POST.
Результати ізольованих перевірок на Python 3.13.18 і 3.9.6: [TESTING.md](TESTING.md).
Умови перевірки: [TESTING.md](TESTING.md). Реальні інтеграції перевіряються окремо.

## Навантаження та межі

- Порожній запуск читає тільки список/лічильники діалогів, без історій.
- Звичайна перевірка кожні 10 с. Активні чати — кожні 2 с протягом 120 с.
- Типово швидких чатів не більше 4; верхня межа 8. Решта перевіряються раз
  на 10 с. Частіше перевіряється тільки метаінформація активних чатів.
- Історія читається лише при збільшенні лічильника. Кілька повідомлень
  поспіль об'єднуються паузою 1 с; перед надсиланням історія перевіряється ще раз.
- SQL читається для потрібного товару під час консультації та повторно перед
  надсиланням відповіді з даними наявності, а не кожні 2 секунди.
- HTTP 429 спричиняє загальну паузу від 60 с до 300 с; 401/403 зупиняють
  процес. Тривала операція OLX може тимчасово відкласти чергову перевірку.
- Максимум 200 чернеток і обмежена пам'ять діалогів. Локальний SQLite WAL
  зберігає технічний стан; окремий сервер для черги не потрібний.
- Новий чат у спокійному режимі виявляється приблизно за 0–10 с плюс час
  мережі та об'єднання повідомлень. У звичайному режимі відповідь надсилається автоматично.

Дозволені лише оголошення, додані тобою в приватному чаті Repliq або явно
вказані в `advert_ids` у `shop.json`. Telegram-налаштування мають пріоритет.
Для звичайної консультації — тільки нові повідомлення **після початкової перевірки поточного запуску**.
Повідомлення, що надійшли до запуску або під час зупинки, не опрацьовуються.
Старі непідтверджені чернетки після перезапуску скасовуються.
Виняток — уже передані власнику діалоги: вони відновлюють пересилання
від останнього збереженого повідомлення. Кнопка завершення угоди та `/done`
повертають чат боту; `/cancel` залишає його закритим до явного ввімкнення.
Якщо OLX повертає суперечливу історію/час/лічильник, бот пропускає автоматичну
відповідь і повідомляє про необхідність ручної перевірки. Часовий пояс для
часу OLX без зміщення налаштовується через `olx_timezone` (типово UTC).

Після невідомого результату надсилання повторного POST не буде: перевір OLX
вручну. Упевнено гарантувати одноразову доставку при втраті відповіді мережі
без підтримки OLX неможливо. OLX також не надає атомарної операції «надіслати,
якщо після перевірки не було нового повідомлення», тому коротке вікно між
останньою перевіркою і надсиланням залишається.

Звичайна консультація не списує склад і не проводить оплату. Після
підтвердження нового замовлення та адреси може створюватися ТТН НП;
відправлення й облік виконує Ledgerly. Докладно: [SHIPPING.md](SHIPPING.md).
Покупцеві не розкриваються собівартість, маржа або дані інших клієнтів.

`private/` містить токени, параметри клієнтів і тексти чернеток. Каталог має
права 700, файли — 600, папка виключена з Git. Пам'ять і завершені чернетки
очищаються через 30 днів; невизначені надсилання залишаються для розбору.
Для роботи автовідповідача з уже отриманими токенами Cloudflare Tunnel
не потрібний. Він знадобиться лише для авторизації OLX через HTTPS callback.

Для щоденної роботи відкривай **«Запустити автовідповідач.command»**.
**«Запустити Repliq.command»** та **«Публічний запуск Repliq.command»**
відкривають сторінку підключення й тимчасову адресу Cloudflare.
Зміна цієї адреси зберігає чинні токени: оновлювати URI в порталі OLX
потрібно лише перед новою авторизацією. Порожні поля Client ID / Client Secret
зберігають попередні ключі. Зміна самих ключів вимагає нового входу.
У `private/oauth-backup.json` автоматично зберігається одна резервна копія
ключів і останніх отриманих токенів з правами 600. Порожня авторизація її
не перезаписує. Цей файл не публікуй і нікому не надсилай.

# Поточний сценарій: передоплата на картку

Нові замовлення післяплатою: **100 грн на картку**, решта вартості товарів —
при отриманні. Доставка оплачується окремо. Є також повна оплата на картку
та OLX Доставка. За підключення mono автоматично перевіряються лише передоплати
94–105 грн і тільки поки їх очікують. Повна оплата перевіряється вручну в Ledgerly.
Підключення: [MONOBANK.md](MONOBANK.md).
У `shop.json` встановлено `shop.cod_payment = "deposit"`, реквізити залишаються
тільки в `private/payments.json` (`kind: "card"`).

Сценарій оплати невідправленої ТТН вимкнений. Номери замовлень, опис товару
в накладній та передача в Ledgerly збережені. Умови вже створених накладних
автоматично не змінюються: для них потрібна перевірка власником, щоб уникнути
подвійної оплати. Попередній сценарій описаний у [CARRIER_PAYMENTS.md](CARRIER_PAYMENTS.md).

Актуальна інструкція та схема взаємодії з Ledgerly: [SYSTEM_FLOW.md](SYSTEM_FLOW.md).
Оплату й відправлення веде Ledgerly; Repliq консультує та передає лише звернення,
які потребують допомоги. У відкритому діалозі — кнопки **auto / я** та
автоматичне повернення бота після 40 хвилин без дій власника.
