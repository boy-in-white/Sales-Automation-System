# Ручне замовлення

У приватному чаті: `/new_order` або `/stock` → «Нове замовлення / продаж».

1. Кнопками обери ОЛХ / Наложка / ФОП / Офлайн, товар, колір, розмір і кількість.
2. Введи **загальну** ціну за вибрану кількість. Наприклад, 2000,50 за дві штуки.
3. Встав одну ТТН. Для офлайн-продажу цей крок пропускається.
4. Перевір картку й натисни «Зберегти».

Онлайн-замовлення зберігається і резервує склад одразу. У «До відправки» натискай
«Відправлено» лише після передачі посилки. Після цього резерв показується як товар
у дорозі. Склад остаточно списується один раз після «Готово в 1С».

Офлайн-продаж зберігається як чернетка до «Продаж завершено». Перевірка оплати
для замовлень Repliq збережена: резерв створюється автоматично після оплати,
позначка фактичної відправки залишається ручною.

Доступ — лише адміністратору в особистому чаті, без повторного пароля.
Фінансові звіти залишаються захищеними окремим паролем.

Кроки форми зберігаються в наявній SQL-таблиці `inventory_wizards`.
Повторне натискання «Зберегти», старі кнопки і повторна ТТН не створюють другий
запис. Команди `/stock`, `/add_product`, `/new_order` починають відповідний новий
сценарій. Якщо бот перезапустився, останні кнопки форми залишаються придатними.
Якщо Telegram точно відхилив надсилання картки, бот дасть кнопку повторного
надсилання. Якщо результат невідомий через timeout, повторного надсилання немає:
спочатку перевір тему відправлень; SQL-запис і резерв збережені. Технічний стан
`order_submissions.telegram_message_id = -1` позначає саме таку невизначеність.

# Оновлення та старі дані

Нових бібліотек або змін `.env` для цієї форми немає. Таблиці й SQL-представлення
для Repliq зберігають сумісність. Перед оновленням зроби резервну копію через
`backup.create_backup()`.

Для старих помилкових назв товарів:

```sh
python scripts/repair_product_links.py             # тільки перегляд
python scripts/repair_product_links.py --apply     # лише однозначні збіги з фактичним списанням/резервом
python scripts/audit_database.py
```

Виправлення змінює лише зв'язок продажу з основним товаром, зберігає подію аудиту,
не змінює залишки, ціни, FIFO-собівартість або попередні списання.
Для вже опублікованих карток старі callback-и підтримуються. Скрипт
`scripts/refresh_order_cards.py` дозволяє переглянути й оновити відкриті картки
без першого підтвердження; використовуй `--apply` лише з зупиненим Ledgerly.
